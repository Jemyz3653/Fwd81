# Словарь Fwd81

Простые объяснения терминов, которые встречаются в проекте. Пополняется по мере
появления новых слов в коде и документах.

---

### API (интерфейс программирования)
Набор функций, которые одна программа предоставляет другой. Когда говорят «API
Windows» — имеют в виду тысячи функций, которые система даёт программам: открыть
файл, создать окно, запустить поток.

### apiset (контракт)
Библиотека с длинным именем вроде `api-ms-win-core-synch-l1-2-0.dll`, **которой не
существует на диске**. Это виртуальное имя — «контракт». Когда программа просит
функцию из такого имени, загрузчик Windows по внутренней таблице подменяет его на
настоящую библиотеку (обычно `kernelbase.dll`).

Зачем: Microsoft может перекладывать функции между настоящими файлами, не ломая
программы. Для нас важно, что в Windows 8.1 такой механизм **уже есть**, просто
список контрактов в нём короче, чем в Windows 10.

### Application Verifier (проверка приложений)
Встроенный в Windows механизм отладки: система при старте программы подключает к ней
дополнительные библиотеки. Fwd81 использует его как способ попасть в процесс раньше
всех. Побочный эффект: некоторые защиты игр принимают это за отладчик и блокируют запуск.

### bound imports (связанный импорт)
Оптимизация: в файл программы заранее записаны не только имена функций, но и их
вычисленные адреса. Если библиотека изменилась, адреса устаревают и Windows
пересчитывает их заново. Нам это важно, потому что переписывать таблицу импорта
приходится с учётом таких заранее записанных адресов.

### CRT (стандартная библиотека языка C)
Библиотека, откуда берутся `printf`, `malloc`, работа со строками. Она не появляется
в процессе сама по себе — её надо инициализировать. Ядро Fwd81 попадает в процесс
раньше этого момента, поэтому собирается **совсем без неё**.

### delay-load (отложенная загрузка)
Способ подключения библиотеки, при котором она грузится не при старте программы,
а при первом обращении к её функции. Ещё одно место, где адреса функций подставляются
позже и которое нам нужно учитывать.

### DLL (динамически подключаемая библиотека)
Файл с функциями, которыми пользуются программы. `kernel32.dll`, `user32.dll` —
части самой Windows. Наши `fwd81_*.dll` — такие же файлы, только со своими функциями.

### DllMain / точка входа
Функция, которую Windows вызывает у библиотеки сразу после её загрузки в процесс.
У Fwd81 она называется `Fwd81CoreEntry`. Внутри неё разрешена **только регистрация**
перехватов — см. «loader lock».

### DPI (точек на дюйм) и «осведомлённость о DPI»
Насколько мелкий или крупный экран. На экранах высокого разрешения Windows увеличивает
изображение. Программа может сообщить системе, что умеет рисоваться под нужный масштаб
сама — это и называется «осведомлённость о DPI». В Windows 10 появилось несколько новых
уровней такой осведомлённости; их мы воспроизводим поверх того, что есть в 8.1 (веха M5).

### exportdiff
Наш инструмент (веха M1): сравнивает списки функций из System32 Windows 10 и
Windows 8.1 и складывает разницу в `data/missing.json`. Отвечает на вопрос «чего в 8.1
нет». Писать код разрешено только для функций из этого списка.

### IAT (таблица импорта)
Список внутри файла программы: «мне нужна функция `CreateFileW` из `kernel32.dll`».
При запуске Windows проходит по этому списку и подставляет туда настоящие адреса
функций. Fwd81 переписывает эту таблицу, подставляя адреса своих реализаций там, где
система ничего не нашла.

### IFEO (Image File Execution Options)
Ветка реестра, где Windows хранит особые настройки для конкретных программ.
Fwd81 записывает туда указание «при запуске этой программы подключи к ней
`fwd81core.dll`». Файлы системы при этом не трогаются.

### KernelBase.dll
Библиотека, в которую Microsoft начиная с Windows 7 переносит основную часть функций
из `kernel32.dll`. В Windows 8.1 она есть — это одна из причин, по которым задача
вообще решаема.

### LGPL, GPL, MIT
Лицензии на код. Коротко, применительно к нам:
- **MIT** — бери и делай что хочешь.
- **LGPL** — если ты изменил **наш** код, отдай изменения; свой собственный код при
  этом можешь не открывать.
- **GPL** — строже: обязывает открыть весь продукт целиком. Поэтому код из ReactOS
  (он под GPL) брать нельзя, а код из Wine (он под LGPL) — можно.

### loader lock (блокировка загрузчика)
Внутренняя блокировка, которую Windows держит, пока загружает библиотеки в процесс.
Если из точки входа своей библиотеки позвать загрузку другой библиотеки или подождать
чего-нибудь, процесс **зависнет намертво**. Зависание хуже падения: падение видно
сразу, а зависший процесс выглядит работающим.

### Ldr-функции (`LdrLoadDll`, `LdrGetProcedureAddress` и прочие)
Внутренние функции загрузчика Windows внутри `ntdll.dll`. Именно они ищут библиотеки
и функции в них. Fwd81 перехватывает их, чтобы вмешаться ровно в тот момент, когда
система чего-то не нашла.

### ntdll.dll
Самая низкоуровневая библиотека Windows, она есть в процессе всегда и появляется
там первой. Единственная библиотека, от которой разрешено зависеть нашему ядру.

### PE-заголовок (Portable Executable)
Служебная часть в начале каждого `.exe` и `.dll`. Там записано, среди прочего,
«мне нужна Windows такой-то версии» и таблица импорта. Из-за первой записи программа
может не запуститься на 8.1 ещё до того, как дело дойдёт до функций.

### PEB (Process Environment Block)
Служебная структура, которую Windows заводит для каждого процесса. Среди прочего там
лежат номера версии системы — поэтому при подмене версии (спуфе) правится в том числе она.

### SPDX-идентификатор
Строка вида `SPDX-License-Identifier: MIT` в шапке файла, машиночитаемая пометка
о лицензии. У нас её наличие и правильность проверяет `tools/check_licenses.py`.

### System32
Каталог с системными библиотеками Windows. **Fwd81 не трогает его никогда** — ни
одного файла, ни при установке, ни при работе. Проекты, которые подменяют файлы в
System32, умеют убивать систему насмерть.

### UCRT (универсальная библиотека языка C) и KB2999226
Часть стандартной библиотеки C, которую Microsoft вынесла в саму Windows. В Windows 8.1
она появляется только с обновлением KB2999226. Чтобы не зависеть от того, стоит ли это
обновление у пользователя, наши утилиты собираются со **статической** библиотекой — она
целиком внутри `.exe`.

### VerifierDlls
Значение в реестре (внутри IFEO), перечисляющее библиотеки, которые Windows подключит
к программе через механизм проверки приложений. Наш способ попасть в процесс первыми.

### Wine
Проект, позволяющий запускать программы Windows на Linux и macOS. За десятилетия там
написаны реализации огромного числа функций Windows. Лицензия LGPL — та же, что у
нашего ядра, поэтому код оттуда брать законно (с указанием источника в `NOTICE`).

### заглушка (stub)
Функция, которая ничего полезного не делает, но ведёт себя предсказуемо: возвращает
корректный код ошибки или разумное значение и пишет о себе в журнал. Это осознанное
решение, а не «доделаем потом».

Заглушка, которая молча врёт «всё получилось», в проекте запрещена: программа,
получившая такой ответ, сломается позже и в другом месте, и найти причину будет нечем.

### спуф версии
Подмена номера версии Windows, которую система сообщает программе. Нужна против
искусственных проверок «работаю только на Windows 10». По умолчанию выключена, потому
что часть программ от вранья ломается сильнее, чем без него.

### сторож
Наш внутренний термин: скрипт-проверка, который механически ловит нарушение правила
проекта. В Fwd81 их пока два: `tools/check_image.py` (от чего зависит собранный файл
и на какой Windows он пойдёт) и `tools/check_licenses.py` (лицензионная граница).

Правило проекта: сторожа проверяют не рассуждением, а поломкой — ломают ровно то, что
он должен поймать, и убеждаются, что он упал **и назвал имя виновника**.
