# Снять с виртуальной машины 8.1 (для M1 и M3)

Что и как перенести с настоящей Windows 8.1 (VMware) на хост, где идёт сборка.
Официальная 8.1 с образа Microsoft, база чистая — доверяем.

Claude Code работает на хосте (Win11) и внутрь гостя команды не выполняет.
Поэтому команды в госте запускаешь **ты**; я готовлю и разбираю результат.

---

## 0a. Свежесть 8.1: обновить ДО снятия копии

8.1 — EOL (последние публичные обновления ~январь 2023). Реальные машины на 8.1
стоят **полностью обновлённые**, замороженные на финальном уровне — под них и
чиним. Поэтому **сначала догнать Windows Update** (или поставить последний
месячный накопительный пакет вручную, если серверы WU капризничают — TLS тут
бывает рвётся, это сеть, не ОС), и только потом копировать System32 и снимать
адреса. Иначе `missing.json` и адреса `ntdll` будут от RTM — не от той 8.1, на
которой реально запускают софт, и всё придётся переснимать после обновления.

## 0b. Снапшоты (в ВМ надёжнее и мгновеннее точки восстановления)

Снимков можно несколько, они дешёвые:

1. **Сейчас, до всего** — снапшот `pristine` (чистая 8.1 как есть).
2. **После Windows Update** — снапшот `clean+updated`. Это **базовый снапшот для
   боевого M3**: к нему откатываемся после каждого прогона хука/IFEO, потому что
   боевой тест идёт на обновлённой 8.1.

Перед боевым M3 в госте страхуемся **снапшотом**, а не (только) точкой
восстановления: в ВМ откат к снапшоту мгновенный и надёжнее. Порядок боевого
прогона: откат к `clean+updated` → прогон → разбор → снова откат.

## 0. Один раз: общая папка VMware

Через неё ходят файлы в обе стороны.

1. В VMware Workstation: **VM → Settings → Options → Shared Folders → Always
   enabled → Add**.
2. Папка хоста: `C:\Fwd81\vm-share` (создай, если нет), имя общей папки: `fwd81`,
   галка **Enable this share** и доступ на запись (сними «Read-only»).
3. В госте 8.1 она видна как `\\vmware-host\Shared Folders\fwd81`. Удобно смапить
   на диск, в госте от обычного пользователя:
   ```
   net use Z: "\\vmware-host\Shared Folders\fwd81"
   ```
   Дальше в примерах — `Z:`.

Если VMware Tools в госте не стоят — поставь их (VM → Install VMware Tools),
иначе общей папки не будет.

## 1. Копия System32 с 8.1 (разблокирует M1 и снятие адресов для M3)

`exportdiff` читает `*.dll`, поэтому достаточно всех DLL из System32 (включая
`ntdll.dll` — она нужна для адресов загрузчика M3).

**В госте 8.1** (обычного пользователя хватает, это чтение), в cmd:

```
robocopy C:\Windows\System32 Z:\system32-win81 *.dll /R:1 /W:1 /NP /NFL /NDL /XJ
```

- `/R:1 /W:1` — не залипать на занятых файлах (пара DLL в работе может
  пропуститься, это нормально: `exportdiff` спокойно переживёт нехватку
  отдельных файлов);
- `/XJ` — не ходить по точкам соединения;
- копируется только верхний уровень `*.dll`, подкаталоги не нужны.

Объём — несколько сотен мегабайт, займёт минуту-другую.

**Зафиксируй версию ntdll этой ВМ** (для M3 адреса берём именно от неё):

```
powershell -c "(Get-Item C:\Windows\System32\ntdll.dll).VersionInfo.FileVersion"
```

Пришли мне эту строку (например `6.3.9600.XXXXX`). Если совпадёт с уже лежащей у
меня копией (6.3.9600.20718) — переиспользую; если нет — адреса снимаю с новой.

**На хосте** (это сделаю я): переносю `Z:\system32-win81\*.dll` в
`C:\Fwd81\data\system32-win81\` (верхний уровень — туда, где их ждёт `exportdiff`
по умолчанию). После этого гоняю `exportdiff all` → настоящие `missing.json`,
`coverage.md`, база для `fwd81diag` — это и есть хвост M1.

> Замечание: копия кладётся в `data\system32-win81\` (НЕ в репозиторий — каталог
> gitignored). Старую вложенную копию `data\system32-win81\System32\` при
> расхождении версий уберу.

## 2. Адреса и смещения загрузчика 8.1 (для боевого M3)

Отдельного действия в госте НЕ требует: адреса я снимаю **на хосте** с
скопированной `ntdll` (тем же `dbh` + `capstone`, как снимал для Win11). От тебя
нужна только сама `ntdll` (она уже в копии System32 из шага 1) и её версия.

Результат — 8.1-адреса `LdrpLoadDependentModuleInternal`, снаппинг-входа,
проверка «через пролог или по смещению» и само смещение (на Win11 было `+0x350`,
на 8.1 будет другое). Занесу в `architecture.md` рядом с win11-значениями.

## 3. Боевой прогон M3 (позже, когда хук готов)

Цикл на каждую итерацию:

1. **хост:** собираю `fwd81core.dll` (экспериментальную/боевую по ситуации),
   `fwd81cli.exe`, synthetic → кладу в `C:\Fwd81\vm-share\m3\` + скрипт прогона;
2. **гость:** запускаешь скрипт (для пути IFEO — из cmd **от администратора**);
   скрипт делает enable/запуск/disable/uninstall и копирует
   `%LOCALAPPDATA%\Fwd81\logs\fwd81.log` в `Z:\m3\`;
3. **хост:** читаю `vm-share\m3\fwd81.log`, разбираю, какие функции сработали и
   дошёл ли synthetic до конца.

Для IFEO в госте те же гарантии, что на Win11, но страховка — **снапшот ВМ**
(`clean+updated`, откат мгновенный), а не точка восстановления: перед прогоном
откат к снапшоту, чёрный список критических процессов в `enable`, `uninstall`
начисто, Defender не обходим.

**Опционально:** если дашь учётку гостя и подтвердишь VMware Tools, могу гонять
прогоны с хоста через `vmrun` (`copyFileHostToGuest`, `runProgramInGuest`,
`copyFileGuestToHost`) — тогда ручной шаг 2 не нужен. Для чувствительных
IFEO-шагов, вероятно, захочешь смотреть сам — решай.
